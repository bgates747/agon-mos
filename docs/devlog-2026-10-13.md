## TX-015 — confirmed diagnostic attribution defect and correction

Executive finding: a definite fixture bug is reproduced and corrected. The
old fixture blamed the current case for flags accumulated since MOS boot.
The precise origin/timing of the original physical framing/BREAK indication
remains unknown because its report has no pre-test baseline. It is not valid
to conclude either that the UART test generated those bits or that startup did.

Zilog PS015317-0120 printed pp.120-121 define 0x98 as ERR, BI and FE. It does
not include the overrun bit. Source trace shows read_lsr ORs those flags into
tx_rx_errors from every legacy/async status read. BSS starts clear, but neither
open nor close establishes an epoch. The original fixture checks the lifetime
byte only after the first blocking case and verification, then silently holds.

Native-instruction reproduction against the exact accepted ROM SHA-256
29a21ca0e2780a2fda1d7a0530c31a4fcaa90f598d25c483d291ef8285ef44df seeds
only the prior software latch with 0x98, transmits/drains/closes cleanly with
zero hardware-model errors, and confirms the latch remains 0x98. The original
fixture condition therefore fails without a new UART error. Evidence is under
build/uart0-bench/stale-reproduction.txt and diagnostic-regression.txt. The final
runner executes 14 reference-ROM cases and 27 revised-ROM cases successfully.

Added tx_diag_take as a backwards-compatible minor-1 API extension: table
length 46, new pointer at offset 43, feature bit 2. It atomically samples pending
LSR/MSR, returns packed flags in HL, and clears only the captured software
latches. It requires the async session closed and refuses BUSY without status
reads when open, preserving a pending CTS wakeup. No RX byte is read, FIFO is
flushed, parser is reset or retained source is freed. Native controls cover
prior flags, repeated fresh bits, unread RX retention, both IFF states and
open-session CTS-edge preservation.

The fixture checks API 1.1, prints/saves setup flags in baseline.dat, establishes
per-case epochs and prints a failed case's RX bits. It still fails for fresh
errors. The 148-byte bench.dat layout is unchanged. baseline.dat must be retained
and renamed on repeat runs. The old API 1.0 MOS produces an explicit installation
message rather than attempting an unavailable operation. This correction needs
manual installation of the revised MOS; a fixture reload alone is insufficient.
