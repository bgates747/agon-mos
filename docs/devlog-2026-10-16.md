## N-007 [x] Off-device boot audit and proven baud correction

Found a definite firmware error independent of any possible flash interruption.
The adopted native foundation's `src/uart.c` multiplies `16 * baudRate` at
24-bit width before assigning to UINT32. At 1152000 it wraps to 1654784 and
programs divisor 11 instead of 1, leaving the physical connection eleven times
too slow. The general-poll exchange cannot complete before the MOS banner.
Our qualification should have caught this before hardware deployment.

Executed actual linked UART0/UART1 routines on the retained independent CPU
oracle. The withdrawn candidate and clean native control both fail at 1048576
and 1152000 baud, while lower-rate controls pass. Widened an operand before
multiplication in both routines, preserving the file's CRLF line endings.
The corrected image programs all 14 expected divisor cases correctly.

The same final harness executes reset/startup with cold and retained RAM,
checking initialized data, cleared BSS, default vector table and heap/stack
bounds. A baud-aware minimal peer refuses the old speed: both old images

palette replies. Its actual UART ISR preserves registers/stack. Timer reload is
