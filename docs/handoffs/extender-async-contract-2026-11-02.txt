Submission: exclusive foreground producer, singleton explicit session, three
nonblocking descriptors. reserve returns ticket or BUSY; it accepts no source.
publish(ticket,source,length) atomically queues borrowed immutable RAM and defines
byte-stream order. Published work is accepted, not necessarily started or
finished. BUSY leaves unaccepted source caller-owned. No waiting-request queue,
fairness broker or readiness callback is currently provided; caller retains
work and retries. Do not infer a completion notification grants pipe admission.
Fairness among unrelated producers would be new scope, preferably in one owner
broker using bounded queues/credits rather than competing UART owners.

Source RELEASED means all source bytes copied into UART hardware: memory may
be reused then, even if tail remains on wire. reap frees its metadata slot.
poll_drain requires empty published queue AND UART TEMT. Neither proves remote
receipt or command execution. Use an already-needed ordered reply only where
remote completion matters; no mandatory new per-transfer acknowledgements,
CRCs/checksums or packet framing were introduced by this async sender.

FIFO/refill: eZ80 UART hardware FIFO holds16bytes. Service requires THRE (empty),
checks hardware CTS input in software, and writes at most16 total bytes per
service. Default policy checks CTS before each byte; optional batch16 checks
before each admitted block (also descriptor boundaries). It does NOT authorize
an arbitrary whole-transfer unguarded burst. TX-empty interrupts refill; modem
CTS-change interrupts resume blocked sends; RX runs the existing MOS state
machine in the combined handler. CTS is a readiness level, not a per-byte
receiver acknowledgement. Port-C/PARLIO strobes/acks require separate source/
edge analysis in each direction; our UART findings do not diagnose those costs.
No calibrated physical CTS margin is claimed. Actual ISR budgets: <=8 cause
reads, <=16 RX bytes, <=one16-byte TX refill per entry. Foreground kick/pump
provides progress with interrupts masked; do not put SD/rendering/long producers
inside an app ISR. Public API is foreground ADL=1 MBASE0; arbitrary app ISRs
unsupported. Synchronous compatibility output serializes behind earlier queued
bytes. Preparing full command packets prevents another producer splitting a
header from its payload; byte-stream serialization alone cannot infer application
command boundaries or allow arbitrary multi-producer interleaving.

Cancellation: reserved or wholly unstarted transaction only; ACTIVE returns
BUSY. Normal close/OSCLI/app return drains accepted data while retaining source
memory, then closes/restores stock vectors and policy; a permanent CTS stop can
wait indefinitely. Reset discards RAM state and returns stock-disabled startup;
whole-board reset also resets VDP parser. No remote cancellation/resume or
CPU-only parser-recovery guarantee. Monotonic descriptor tickets avoid normal
stale-handle reuse; retained application pointers must not survive teardown.

Current experimental callback event means source consumed, not wire-drained or
remote-executed. Direct callback may run during initial foreground service or
later UART ISR, always DI with reentry rejected; only bounded posting of ID/flag
is allowed. Notification may precede write return. Foreground event dispatch is
safer for arbitrary app work but remains application-serviced completion polling;
we will not label it automatic interrupt dispatch. Registration/config changes
require quiescence, before publication; keep callback/context valid until retired.
Logical write IDs distinguish calls from FIFO chunks. Mode teardown suppresses
pending app callback references before draining/return. Exactly-once delivery
and ordering are tested; no new readiness callback is implied.

Explicit copied RST18 mode copies into three256-byte buffers, allows immediate
caller source reuse, and waits for space (backpressure) if necessary, chunking
larger calls. Default RST18 stays synchronous; ordinary async open does not
change it. Borrowed path avoids copying. Prototype costs are roughly1.5KiB
additional MOS image and0.8KiB BSS versus the accepted image, subject to final
build accounting; this is NOT an EMOS space acceptance. Fixed-copy code is being
optimized and off-device instruction tests continue. Prefer extracting wrapper/
completion semantics rather than copying our whole MOS adapter into EMOS.
