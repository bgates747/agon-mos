DISCOVERY AND COMMON SETUP
All calls below are eZ80 ADL=1, MBASE=0 register ABI, NOT C stack function
pointers. Use an explicit assembly shim for C/C++. Operation pointers are
24-bit little-endian entries at BYTE offsets in the ROM table.

Discover via MOS getfunction50h, B=13h C=0. Require A=OK and HL!=0; call that
discovery function to obtain HL=table. Validate UTX1, major1, minor>=3,
length>=69, flags bit4, and batch16 capability (bitmap at52, bit15).
Keep a synchronous stock-MOS fallback when unavailable; do not treat the older
ABI1.2 image as supporting these appended functions.

Open via pointer at offset13; require A=OK. New sessions default to CTS batch1.
At quiescence/TEMT, select batch16 via offset46, B=16; require A=OK. BUSY means
retry later from foreground with interrupts enabled, not discard pending audio.
General status A: OK0, BUSY1, INVALID2, CLOSED3, CONTEXT4.

Configuration requires an open session, all descriptors free, no synchronous
scope/barrier/active copied write, and UART TEMT. Only three descriptor slots
exist. IX/IY, shadow banks and incoming foreground IFF are preserved. Treat
other primary registers as scratch except documented results. Do not mix
convenience logical IDs with the older reserve/publish ticket handles.

BORROWED WRITE: NO PAYLOAD COPY
Pseudocode, with explicit register shims behind these descriptive names:

  discover_v1_3(); open(); select_batch(16);
  configure(mode=BORROWED, delivery=DIRECT, callback=post_only, context=ctx);
  status, id = write_borrowed(immutable_packet, packet_length);
  if BUSY: keep the packet and retry from foreground later;
  if OK: do other work; keep the packet unchanged until its release notification;
  after notifications, poll_drain_until_OK(); close_until_OK();

The source must lie wholly in [040000h,0BC000h), without wrapping. A successful
write automates the original reserve/publish/status/reap mechanics. Completion
allows source reuse. A direct callback can execute before submission returns,
so prepare its state before calling and use its supplied ID; do not assume you
can register the returned ID in an application map before any notification.
Failed attempts can leave ID gaps. IDs are24-bit, session-local opaque values,
not persistent report numbers; indefinite wraparound is not established here.

For foreground event delivery instead, configure B=0 C=0 HL=0. Periodically
take events at63, then dispatch your own callback AFTER take returns in ordinary
foreground. This polls completion events, never individual16-byte refills.
Untaken events retain the bounded descriptor slots and can cause BUSY; service
them while producing, and consume them before closing. There is no automatic
foreground callback scheduler hidden in MOS.

COPIED RST18: FAMILIAR WRITE CALL, EXPLICIT OPT-IN
  discover_v1_3(); open(); select_batch(16);
  configure(mode=COPIED_RST18, delivery=DIRECT, callback=post_only_or_NULL,
            context=ctx);
  rst18_write(packet, length);   // existing fixed-length output calling form
  reuse_packet_immediately();
  optional_id = last_accepted_write_id();
  do_other_work();
  poll_drain_until_OK(); close_until_OK();

The existing fixed-length and delimited RST18 forms are supported. There are
three256-byte MOS-owned buffers (768bytes total), copied with LDIR before
publication to the same OTIRX sender. A call larger than the queue waits for
room and proceeds in chunks; source reuse is safe when the call returns, but
the call is not guaranteed to return immediately. This is not an unbounded
queue. Each nonempty logical write gets one ID/optional callback, independent
of internal copied chunks and16-byte FIFO refills. Copied mode requires C=1;
HL=0 selects no callback with automatic retirement. B=1 C=0 is INVALID because
retained events could exhaust all slots before the producing call returns.

The copied callback reports consumption of the MOS-owned copies, not the
earlier point when the original application source becomes reusable at return.
tx_write_last is for associating copied logical writes; a callback may already
have fired before the application asks for that ID. Nonzero-MBASE output keeps
the synchronous compatibility path and does not get a new callback/ID. Existing
masked-IFF foreground compatibility pumping remains; this does not authorize
calling the async API from an application ISR.

CALLBACK, ORDERING AND LIFETIME RULES
Direct callback input: A=RELEASED(4), HL=logical write ID, DE=registered context.
It can run during masked foreground service OR the MOS UART ISR, always with
interrupts disabled. It must preserve ADL/MBASE, leave interrupts disabled,
return normally and only post bounded state. MOS saves primary/shadow register
banks and indexes. API reentry returns CONTEXT. No SD access, rendering, MOS
output, recursive sends, waiting or other substantial work in this callback.
A normal compiled C function needs an appropriate assembly callback shim.

Source consumed is NOT wire drained and is NOT VDP command execution complete.
offset31 poll_drain returns OK only with queue empty AND UART TEMT; a command
execution fence needs the relevant VDP reply. All accepted traffic stays ordered.
Keep command headers and payloads ordered through the sole MOS UART owner.
Jukebox's scheduling ISR should post due work, not send bytes or call these APIs.
Opening still excludes installed MOS keyboard callbacks; use MOS keyboard state/
polling, or explicitly handle exclusion. Completion callbacks do not remove it.

Close at34 requires completion records resolved and wire drained, then clears
configuration and restores stock dispatch. OSCLI/application return suppresses
pending callback delivery before draining accepted sources and restoring stock;
reset clears the mode. Do not promise a callback after teardown/reset. Keep
callback code/context alive until delivered or explicitly retired. Default
startup remains the proven stock transport path until explicit activation.
